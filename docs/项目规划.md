# OfferPilot（暂定名）· 秋招求职助手 · 项目规划

> v0.2 · 2026-09-27。需求与技术栈均已确认（见 §2、§7）。

## 1. 项目定位

- **性质**：开源作品集项目 —— 代码质量、文档、架构都要达到"能写进简历、面试有亮点可讲"的水准。
- **一句话**：把 **AI 模拟面试 + 半自动投递 + 求职进度看板** 做成闭环的秋招 Web 应用。
- **差异化**：调研显示现有开源项目都是单点工具（投递脚本、面试机器人二选一），秋招进度看板几乎空白；本项目主打**闭环**与**安全的半自动设计**。
- **用户**：先保证单用户（自己）体验顺滑，架构上保留多用户与鉴权。

## 3. 功能模块

### F1 用户与设置
- 注册 / 登录（JWT）。
- LLM 配置：Provider（GLM / DeepSeek / Qwen…）+ Base URL + API Key（加密存储）+ 模型名，支持多套配置切换。

### F2 简历中心
- 上传 PDF / Word → 解析为结构化 JSON（基本信息 / 教育 / 实习 / 项目 / 技能）。
- 在线编辑解析结果，支持保存多个简历版本。
- 面试与投递模块共用此处数据。

### F3 模拟面试（MVP 核心）
- **创建面试**：选择简历版本 + 面试类型（简历项目深挖 / 技术八股 / 算法 / 场景设计）+ 目标岗位 JD（可选，用于定向提问）+ 难度与轮次。
- **文字对话面试官**：SSE 流式输出；面试官具备追问策略 —— 简历深挖按 STAR 追问细节，技术题按难度阶梯递进；支持中途暂停 / 继续 / 提前结束。
- **评分与复盘报告**：结束后生成 —— 总分 + 分维度得分（表达、深度、广度、正确性）、逐题点评与参考答案要点、薄弱点清单、改进建议。
- **历史与回放**：会话记录回放、同简历多次面试的提升对比（可选）。
- 后期（M4）：语音模式（TTS + ASR），架构预留流式语音通道。

### F4 岗位与投递（M3，难度最高）
- **求职意向**：岗位关键词、城市、期望薪资、每日投递上限等。
- **岗位抓取**：Playwright 在登录态下抓取搜索结果（Boss 直聘 → 智联 / 前程无忧 / 猎聘），去重入库。
- **匹配打分**：LLM 结构化输出匹配分（0-100）+ 推荐理由 + 风险点，按分排序。
- **打招呼语**：按 JD + 简历自动生成，可编辑。
- **确认队列**：打分结果进入队列，人工勾选 / 批量确认后才生成投递任务（半自动的核心）。
- **投递执行器**：后台任务 + Playwright 复用登录态（storage_state，首次人工扫码登录），逐条执行，随机延时 + 限频，执行截图留痕，失败重试，异常自动暂停转人工。
- **风控红线**：不破解验证码（遇到即暂停并通知）、每日限额、操作拟人化；文档明确声明仅供学习交流。

### F5 进度看板（M2）
- 投递记录手动 CRUD；状态机：**已投递 → 已查看 → 笔试 → 一面 → 二面 → HR 面 → Offer / 已挂 / 流程终止**。
- 状态每次流转自动写入时间线（事件表）。
- 视图：**投递漏斗图**、状态分布、公司时间线、面试日程、周投递量与转化率统计。
- 与 F4 联动：自动投递成功后自动生成投递记录。

### F6 通知提醒（M4+，可选）
- 面试日程提醒：邮件 / Server酱 / 企业微信 Webhook。

## 4. 系统架构

```
┌──────────────── React SPA (Vite + TS) ────────────────┐
│  简历中心 │ 模拟面试 │ 投递中心 │ 进度看板 │ 设置        │
└───────────────┬───────────────────────────────────────┘
          HTTP REST + SSE（面试流式输出）
┌───────────────▼────────────────┐      ┌────────────────┐
│ Python 后端 (FastAPI)           │─────▶│ LLM API        │
│  · REST API / SSE              │      │ GLM/DeepSeek/  │
│  · 业务服务层 + LangChain 封装  │      │ Qwen（可配置）  │
│  · ORM                         │      └────────────────┘
└──────┬─────────────────┬───────┘
       │                 │
┌──────▼─────┐   ┌───────▼──────┐    ┌─────────────────────┐
│  MySQL 8   │   │ Redis（队列） │───▶│ Worker 进程           │
└────────────┘   └──────────────┘    │  · 岗位抓取           │
                                     │  · Playwright 投递    │
                                     └─────────────────────┘
```

- 面试对话流式输出用 SSE（比 WebSocket 简单，单向推送够用）。
- 耗时任务（抓取、投递、报告生成）全部异步化，不阻塞 API。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 平台风控 / 封号 | 半自动确认、每日限额、拟人化延时、遇验证码即暂停转人工；支持"仅抓取不投递"模式；README 声明仅供学习 |
| 平台页面改版导致自动化失效 | 平台适配器模式，选择器集中配置，单平台失效不影响其他 |
| LLM API 成本失控 | 国产低价模型；LLM 调用日志记录 token 消耗；前端展示用量 |
| 开源同质化、没人看 | 主打闭环差异化 + 优质 README（GIF 演示）+ 一键部署体验 |
